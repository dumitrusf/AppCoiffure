## Projet 1 — Bienes Raíces

### Description générale

Projet de site immobilier complet, construit progressivement depuis l'intégration HTML/SASS jusqu'à la mise en place d'un back-end PHP avec base de données MySQL, CRUD de propriétés, authentification, upload d'images, puis refactorisation orientée objet avec Active Record.

### Compétences AT2 potentiellement couvertes

- Développer la partie back-end d'une application web ou web mobile.
- Développer des composants d'accès aux données SQL et NoSQL.
- Mettre en place une authentification utilisateur.
- Structurer une application avec PHP, MySQL, POO, autoload Composer et Active Record.

## Première analyse du projet 1

### Points forts pour le dossier professionnel

- Projet plus complet que le petit exemple MongoDB.
- Présence d'un vrai back-end PHP.
- Base de données relationnelle MySQL.
- CRUD complet sur des propriétés immobilières.
- Formulaires avec `$_POST` / `$_GET`.
- Validation et sanitisation des données.
- Upload d'images et gestion de fichiers.
- Authentification avec hachage de mot de passe.
- Sessions PHP et protection des pages.
- Évolution vers une architecture orientée objet.
- Composer, autoload, namespaces, héritage, Active Record.
- Accès aux données avec MySQLi / PDO.
- Architecture MVC avec modèles, contrôleurs, routeur, vues et layout.
- Gestion de plusieurs entités métier : propriétés et vendeurs.
- Envoi d'e-mails avec PHPMailer et Mailtrap.
- Protection des routes dans une architecture MVC.
- Phases de tests, optimisation et préparation au lancement.
- Potentiel de captures très fortes pour le DP.

### Points faibles / risques

- Projet long à terminer.
- Beaucoup de front-end au début ; il faudra sélectionner seulement les parties back-end pour le DP.
- Risque de perdre du temps si l'objectif est de tout refaire parfaitement.
- Il faudra éviter de présenter les premières sections HTML/SASS comme exemple principal d'AT2.

### Captures pertinentes si ce projet est retenu

- Diagramme ou tables MySQL dans MySQL Workbench.
- Fichier de connexion à la base de données.
- Formulaire de création de propriété avec validation.
- Code d'insertion en base de données.
- Listing dynamique des propriétés depuis MySQL.
- Code d'upload d'image et génération de nom unique.
- Formulaire de login.
- Code de hachage / vérification du mot de passe.
- Protection de page avec `$_SESSION`.
- Classe `Propiedad`, Active Record ou modèle POO.
- Routeur MVC et association URL / méthode de contrôleur.
- Contrôleur de propriétés ou de vendeurs.
- Formulaire de contact + envoi via PHPMailer / Mailtrap.
- Protection de routes dans le contrôleur d'authentification.

### Verdict provisoire

Ce projet semble **très fort pour l'Activité-type 2**, bien plus complet que l'exemple MongoDB actuel. Il couvre à la fois le CRUD, l'accès aux données SQL, les formulaires, la sécurité de base, l'authentification, les sessions, l'upload de fichiers, la structuration POO, l'architecture MVC, l'envoi d'e-mails, la protection de routes et la préparation au lancement.

Il pourrait devenir un excellent **exemple principal** pour l'AT2. Les sections les plus utiles pour le DP seraient probablement : **30 (CRUD propriétés)**, **31 ou 43 (authentification)**, **34 à 39 (POO / Active Record / CRUD)**, **41 (MVC)** et **42 (emails)**. Il ne faut pas tout documenter : il faudra sélectionner les preuves les plus fortes.

## Première analyse du projet 4

### Points forts pour le dossier professionnel

- Projet MongoDB beaucoup plus complet que l'exemple actuel de scripts `mongosh`.
- Stack Node.js / Express / Handlebars / MongoDB Atlas / Mongoose.
- Serveur, router et moteur de templates.
- Variables d'environnement.
- Connexion à MongoDB Atlas.
- Modèles Mongoose : offres, recruteurs, candidats.
- CRUD complet des offres d'emploi.
- Authentification avec Passport.
- Validation et sanitisation.
- Panel d'administration recruteur.
- Autorisation : vérifier que le recruteur est propriétaire de l'offre avant suppression.

- Validation de type et taille de fichier.
- Candidatures avec CV PDF.
- Reset password avec token et NodeMailer.
- Recherche d'offres.

### Points faibles / risques

- Projet ancien possible : risque d'adapter certaines dépendances Node / Express / Mongoose / Passport.
- MongoDB Atlas peut demander une configuration externe (cluster, utilisateur, IP whitelist, URI).
- Projet moins riche que DevWebCamp sur les statistiques / paiements, mais plus direct et cohérent pour un exemple MongoDB.
- Il faudra vérifier que le code fonctionne avec les versions actuelles de Node et Mongoose.

### Captures pertinentes si ce projet est retenu

- Structure du serveur Express + router.
- Connexion Mongoose à MongoDB Atlas avec variables d'environnement.
- Modèle `Vacante` ou modèle de recruteur.
- Formulaire de création d'offre.
- Stockage d'une offre en base MongoDB.
- Liste d'offres depuis MongoDB.
- Formulaire de login + configuration Passport.
- Code d'autorisation du panel.
- Vérification du propriétaire avant suppression d'une offre.
- Upload profil avec Multer.
- Candidature avec CV PDF.
- Reset password avec token et NodeMailer.
- MongoDB Compass / Atlas montrant collections et documents.
- Déploiement.

### Verdict provisoire

devJobs est **le meilleur remplaçant naturel** du petit exemple MongoDB actuel. Il garde l'angle NoSQL, mais avec un vrai back-end applicatif : serveur Express, routes, templates, modèles Mongoose, authentification, autorisation, upload de fichiers, candidatures, e-mails, recherche et déploiement.

S'il fonctionne correctement dans l'environnement actuel, il est beaucoup plus convaincant pour le DP que le module `mongosh` simple. Il peut couvrir à la fois **Développer des composants d'accès aux données SQL et NoSQL** et **Développer la partie back-end d'une application web sécurisée**.
